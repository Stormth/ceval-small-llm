# 实验协议

本文件是正式实验前冻结的协议。开始跑基线后，除明确记录的 bug 修复外，不修改以下内容。

## 1. 冻结项

| 项目 | 冻结值 |
|---|---|
| 模型 | `Qwen/Qwen2.5-0.5B-Instruct` |
| 评测数据 | `data/subset.jsonl`，200 题 |
| 学科 | 8 科 × 25 题 |
| 数据分割 | C-Eval `val` |
| 提示系统消息 | `你是一个严谨的中文考试答题助手。` |
| 基线提示 | `prompts.build_baseline_prompt` |
| 基线解码 | greedy，`max_new_tokens=128` |
| 答案解析 | `parsing.parse_answer` |
| 正确性 | 提取选项 == 参考答案 |
| 格式有效率 | 能提取出唯一选项的题数 / 总题数 |
| 失败处理 | 保留在分母中，计为错误，并记录异常 |

## 2. 数据规则

- 子集在跑任何模型之前生成并写入 `data/subset_manifest.json`。
- 不使用 `test`，因为标签不公开。
- 少样本示例只来自 `data/fewshot_examples.jsonl`（C-Eval `dev`），不得来自评测子集。
- 不按模型答对与否挑题；不删除答错、截断或格式无效的样本。
- 所有正式配置使用同一份 `subset.jsonl` 和同一个 SHA256。

## 3. 提示与生成规则

### 基线

官方风格零样本提示：

```text
以下是中国关于{学科}考试的单项选择题，请选出其中的正确答案。

{题目}
A. ...
B. ...
C. ...
D. ...

答案：
```

### 改进 1：严格格式

只改变任务描述和输出约束，要求只输出一个选项字母。

### 改进 2：少样本

每科固定 3 条 `dev` 示例，示例顺序固定，示例内容不包含评测题。

### 改进 3：自检

第一次正常作答；第二次把题目、选项和第一轮输出交给模型复核，要求最后一行输出最终答案。两次调用都计入耗时和调用次数。

### 改进 4：多次采样投票

同一提示采样 3 次，温度 0.7，按多数票选择最终答案；平票时选择最早出现的有效答案。记录 3 次调用和全部原始输出。

## 4. 消融

采样次数消融：`n=1/3/5`，全部使用 `do_sample=true`、`temperature=0.7`。观察准确率、格式有效率、总耗时、平均耗时、调用次数和输出长度。`n=1` 是参数曲线的一端，不等同于 greedy 基线。

## 5. 需要报告的指标

- 总体准确率
- 各学科准确率
- 答案格式有效率
- 截断率
- 异常/超时/解析失败数
- 总耗时、平均单题耗时
- 模型调用次数、平均每题调用次数
- 平均输出 token 数

## 6. 运行与日志

每次正式运行必须保留：

- `run_meta.json`：配置、模型、git commit、环境版本
- `per_question.jsonl`：逐题完整输入、原始输出、提取答案、参考答、得分、耗时、异常状态
- `summary.json` / `summary.md`：总体、分学科、分类别汇总
- `outputs/comparison.csv`：跨实验对比表

## 7. 失败与重跑

- 单题异常：捕获并记录，保留在分母中。
- 进程中断：使用同一 `run-dir` 重跑，默认按 `sample_id` 跳过已完成题。
- 系统故障导致整批无效：统一重跑整个配置，不能只重跑错题。
- 发现评分 bug：说明原因，对所有相关配置统一重新评分，不能只修改某个方案。
- 生成达到长度上限：保留回答并评分，同时标记 `truncated=true`。

## 8. 公平对照检查

每个改进在汇报前逐项确认：

- [ ] 与基线使用同一份 `subset.jsonl`
- [ ] 使用同一个解析器和评分脚本
- [ ] 除研究因素外，模型、精度、设备、最大输出长度一致
- [ ] 记录调用次数和耗时
- [ ] 记录失败和负结果
- [ ] 报告结论不超出 200 题目集
